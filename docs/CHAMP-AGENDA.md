# CHAMP supplied agenda relationships and timeline

Rich `champ-event-json` normalization and configured event retrieval preserve more than the original compatibility projection. The latter remains unchanged: existing meeting IDs, v1 item titles and combined document links retain their original output.

The rich meeting's `agenda_items` now retain native `CustomerAgendaItemID`, explicit `Children`/`OrderParentID` hierarchy, displayed order, supplied descriptions and item-associated documents. `CustomerEventID` must match the enclosing event, IDs must be unique and the supplied parent must agree with its tree position. Ambiguous source binding retains the meeting/raw capture and baseline items with `agenda_relationships_availability="unmapped_ambiguous_source_binding"`; it does not invent a parent. Exact original JSON preserves unknown fields, and normalized `source_fields` retain item values without recursively duplicating `Children`.

Documents are associated only when their supplied native media ID, event and `MediaTargetID` agree with that item, and an existing compatibility-mapped document URL matches the supplied location/filename. This adds associations to already supported URLs rather than inventing a new download route. Binary retrieval continues through the existing attachment and origin guards.

The [captured vendor player](capabilities/evidence/champ-public-player/source.json) explicitly defines `ContainerTypeID == 2` as Agenda Item, uses `ContainerID` to select the item, and seeks `TimeStartSeconds`. Rich item `timeline` entries retain the native timeline ID, start/end in seconds and complete source row. Unmatched types/items/events or invalid time intervals stay in `unassociated_timeline`; no speaker, motion, transcript or timezone meaning is inferred. A single valid interval supplies the item's description search segment with a formatted start timestamp; multiple intervals remain explicit and do not invent one preferred anchor.

HTML descriptions are converted to supplied visible text without executing script/style/template content. Search results retain item ID, citation, capture provenance and applicable timestamp. Search can remain partial when attachment/transcript text is unavailable. The final rich normalized hash includes the supplied fields, so a description-only source change changes that digest while preserving native identity. Neutral export/import preserves the rich bundle and raw capture losslessly.

Evidence consists of synthetic actual-engine normalize/configured-fetch/search/export and source-binding cases, the existing saved event JSON and exact captured public player JavaScript. This is captured-version behavior, not proof of a supported vendor integration API, complete event catalog, downloaded media or vendor writes. No new network request was made.
