THE PROBLEM

The record is more than the text.

Meeting information arrives as vendor APIs, public pages, saved responses and attachments. A useful integration needs to carry the identity, capture and limits along with the normalized fields.

QuorumRelay gives applications a shared path from configured sources to usable records, while leaving editorial and canonical decisions with the application.

A SHARED WORKFLOW

From source to
something useful.

Use saved captures or supported bounded reads. Keep the complete result, including its coverage and errors.

01

Discover & retrieve

Read configured sources within explicit dates and limits. Fetch documents or recordings selected from captured relationships.

02

Preserve & normalize

Retain original captures, source identities, citations and unknown fields alongside normalized records.

03

Use & review

Search available fields, export portable bundles, and let your application decide what to save or publish.

engine = create_engine()

CAPABILITIES & BOUNDARIES

Useful by design.
Honest about limits.

Search what is actually available

Search captured metadata and supplied text. Thirteen provider adapters also expose bounded native search; their fields and coverage differ.

Move evidence, not just fields

Use neutral JSON, JSONL and ZIP interchange. CSV and iCalendar projections report their losses.

Writes require a deliberate decision

Supported write adapters use explicit scoped policy, server-owned credentials, a reviewed exact plan and a receipt. Live provider write acceptance is still deferred.

CURRENT STATUS

A development preview,
not a promise of completeness.

Provider coverage is uneven. Some reads need credentials, a guarded browser session or supplied captures; complete catalogs, account access and live writes have not been accepted for every provider.
